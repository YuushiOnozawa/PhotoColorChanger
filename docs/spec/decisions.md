# 製品判断記録

## D-001: 静的なクライアント専用アプリ

**決定:** バックエンドと画像永続化を使わないTypeScript／ReactサイトをGitHub Pagesで公開する。

**理由:** ローカル写真の塗装補助ツールであり、アップロードとサーバー保存をなくすことでプライバシーリスクと運用コストを下げられるため。

## D-002: 画像全体の近似色選択

**決定:** 取得した色に十分近いピクセルを画像全体から選択し、許容範囲と追加／除外ブラシで補正する。

**理由:** 同じ成形色のプラモデル部品が離れた場所にあるため。誤選択はブラシで補正する。

## D-003: 非破壊の変更履歴

**決定:** 元画像を直接変更せず、色変更ごとに独立した並べ替え可能な操作として保持する。

**理由:** 複数色の変更とUndo／Redoが必要であり、初期版に完全なレイヤー編集を入れずに将来の拡張経路を確保できるため。

## D-004: 質感を保つ色変換

**決定:** 変更後の色の明るさを基準にし、元画像の相対的な陰影、ハイライト、質感を保ち、塗装強度を提供する。

**理由:** 目的は平坦な塗りつぶしではなく、塗装後の見た目の確認だから。

## D-005: PC優先のUX

**決定:** 初期版はPCブラウザを最適化対象とし、意味のある独立Sectionと将来のレスポンシブ対応を意識したCSS構造にする。

**理由:** ブラシ補正と履歴編集は大きな画面に向いている一方、将来のタッチ対応をDOM構造で妨げないため。

## D-006: 明示的な縮小上限

**決定:** 長辺4096pxを超える画像は編集前に縮小し、書き出しも縮小後の解像度とする。

**理由:** 複数のCanvasバッファとマスクを使うと、静的ブラウザアプリが一般的な端末で不安定になる可能性があるため。

## D-007: 将来の塗料DBは実行時依存にしない

**決定:** メーカー塗料連携は延期し、追加時はライブAPIではなく、バージョン管理された許諾確認済みの同梱データを優先する。

**理由:** メーカー公式資料には安定した公開RGB／HEX APIが見当たらず、画面上の色は実物塗料の完全な再現ではないため。
